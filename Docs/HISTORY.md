# 历史时间线与电量语义

## 数据来源

- `pmset -g log`：系统 Sleep、Wake、DarkWake、HibernateStats 以及可见的关机／启动事件。
- 服务日志：本工具设置模式 25 并请求睡眠的时间。
- IOPS：应用运行时每分钟采集电量百分比和供电类型。

只解析明确的事件域与内容。`Wake Requests` 是唤醒安排，不是实际唤醒，不能作为区间边界。重复或乱序的导入会去重、排序。

系统日志的保留长度由 macOS 决定。应用无法恢复从未导入、且已被系统清除的数据。

## 区间分类

| 显示 | 依据 | 边界精度 |
| --- | --- | --- |
| 唤醒 | 系统 Wake / DarkWake 到下次 Sleep | 系统事件时间；包含后台维护唤醒 |
| RAM 睡眠（推断） | 睡眠后从 Deep Idle / Sleep 恢复，附近 hibmode=3 | 睡眠区间推断，不证明每一秒的硬件供电状态 |
| 磁盘休眠（实色） | 睡眠前 90 秒内存在工具模式 25 请求，之后 Wake from Hibernate | 开始边界为系统 Sleep；明细同时显示请求时间，不表示 SSD 写入完成时间 |
| 磁盘相关睡眠（浅色） | 历史 Wake from Hibernate，但没有可关联工具请求 | 只确认恢复方式；不能反推此前 RAM→磁盘的确切时刻 |
| 未确认睡眠 | 睡眠未结束或证据不足 | 保留未知状态 |

关机和启动标记可见时会切断区间，不把未观察到的重启空档计入唤醒或睡眠。没有日志证据的空白保持空白。系统未报告的中途供电变化可能无法检测。

## 电量

每个区间显示起点和终点的系统电量。变化单位为**百分点**，例如 96%→95% 表示下降 1 个百分点，不代表消耗 1 Wh 或固定的 mAh。

- 放电合计只使用标记为电池、两端电量齐全且未上升的区间。
- 接电源、已观察到的供电变化、电量上升不计入放电合计。
- 自定义范围切断区间时，切点的电量留空，不按时长线性估算。
- 系统电量常为整数；0 个百分点不代表没有耗电。
- 图表仅连接间隔不超过两分钟、供电来源相同的采样点。睡眠中没有持续采样时不会补造连续电量曲线。

汇总时长是**可见、已归类区间的长度**；“磁盘相关区间”可能包含浅色推断段，不能当作精确测量的磁盘断电时长。界面最多列出最近 300 个区间，CSV 导出当前范围全部区间。

## 存储

当前版本使用用户 Application Support 目录下的 JSON archive，保留 90 天系统事件和分钟采样，不保存到源码仓库。程序只在运行时采样；关闭主窗口仍运行，退出应用后暂停。

CSV 包含时间、状态、时长、端点电量、净下降、供电来源、推断标记、进行中标记与依据。诊断和导出文件可能含进程名或时间信息，反馈问题时只提供相关区间。
