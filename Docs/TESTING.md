# 测试与验证范围

## 自动测试

```bash
make test
```

默认测试不安装 helper、不写生产目录、不安排真实唤醒、不发送真实 sleepnow：

1. helper 的 `--self-test`：供电范围、提前唤醒、用户空闲保护、模式解析和配置序列化。
2. `ControlTests.swift`：临时 socket 往返、内核对端 UID、拒绝响应和不可连接情形。
3. `HistoryTests.swift`：合成事件的去重排序、RAM 配对、工具控制的磁盘边界、历史歧义、时间截断、充电排除、供电变化、重启空档及未完成睡眠。
4. `CommandRunnerTests.swift`：子进程输出、退出码、硬超时、等待期间无 RunLoop 重入、新旧唤醒事件与 DarkWake 原因解析。
5. `HelperRegressionTests.swift`：真实生产通知路由的隔离测试；模拟休眠进程仍运行时处理通知、确认通知、回复 IPC、模拟唤醒后恢复模式并回收子进程。
6. 后台唤醒回归不发送完整唤醒通知：验证到期立即设置模式 25、不启动 sleepnow、自然回睡保留模式、开盖恢复，以及提前唤醒、未知状态、开盖、接电、锁忙和重复通知保护。断言执行小于一秒，不能等原来的 25 秒。
7. `PowerMonitorTests.swift`：能力位与未知状态保护、实际动态状态监听注册。以 root 运行时，在独立测试键上验证真实回调投递；普通用户无权向 configd 写键时明确跳过该项。测试不写 powerd 状态键，临时测试键在结束时删除。

测试数据都是合成数据，不包含开发机器日志或用户标识。socket 测试使用当前 UID，不写死 501，也不依赖仓库所在目录。

`SLEEPBRIDGE_TESTING` 只用于回归测试目标：生产目录被替换为必须显式传入的私有 `/tmp/sleepbridge-tests-*` 目录，IOKit 注册和电源操作由测试替身接管。模拟休眠子进程为 `/bin/sleep 2`。发布构建从不传入此标记，也不包含测试替身。没有通过环境变量切换生产 helper 权限或执行路径的入口。

## launchd 回归

```bash
make test-launchd
```

此测试需本机已登录的 GUI 用户会话。它以当前 UID 在 `gui/<uid>` 临时加载一个唯一标签的 Background LaunchAgent，运行同一隔离回归，结束后卸载。它不加载或替换 system 域中的生产 helper，仍不执行真实电源命令。

CI 运行普通自动测试和 app 构建；不依赖 GUI 会话，不自动执行真实睡眠测试。

## 已完成的硬件验证

在 M1 MacBook Air、macOS 27.0.1 上，已观察到一次手动请求后实际 `Wake from Hibernate` / `hibmode=25`，唤醒后模式恢复为 3，helper 控制接口仍正常。本次源码整理只进行了构建与隔离测试，没有再次触发机器休眠。

这不是跨机型认证。旧版曾完成一次定时完整唤醒后的模式 25 转换，但另一次真实合盖周期只有短暂 DarkWake，未执行转换。1.4.2 针对此路径增加能力监听，完整“合盖 → 到达阈值 → DarkWake → 设置模式 25 → 自然回睡 → Hibernate 恢复”仍需实机验证，自动测试不能替代这一结论。

## 手动验证建议

由测试者保存工作并主动进行。分别记录电源类型、请求时间、系统 Sleep/Wake、HibernateStats、电量和恢复后的模式值。

- 手动磁盘休眠及恢复。
- 提前开盖取消计时。
- 完整阈值转换，分别测试合盖与不合盖、电池与接电源。
- 到期附近用户输入、电源切换、低电量、系统维护唤醒。
- 停用恢复、重启后的状态以及卸载。

只分享相关且已删去个人信息的记录；不要把原始设备历史加入测试 fixture。

自动检查回归覆盖缩短延迟后的日志慢读取、同时接收 ping、操作锁忙时非阻塞跳过、未知原因安全取消，以及新睡眠周期对旧读取结果的失效处理。它不代替合盖后完整硬件周期验证。
